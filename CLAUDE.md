# Своим ходом (tripplan)

Планировщик поездок по России: backend на Python (Starlette), frontend на React + esbuild.
Устройство проекта и API описаны в README.md.

Общаемся с пользователем по-русски.

## Запуск на этом сервере

- Сервер работает как systemd-служба `tripplan` (`/etc/systemd/system/tripplan.service`):
  uvicorn с `--reload` на `127.0.0.1:8000`, запускается при загрузке системы и перезапускается при падении.
  - `systemctl restart tripplan` — после правок в `backend/.env` и каталоге `backend/data/*.json`
    (`--reload` следит только за `.py`, а каталог кешируется в памяти)
  - каталоги `backend/data/*_places.json` хранятся с отступом в 1 пробел и без перевода строки в конце — сохраняйте так же
  - `systemctl status tripplan`, `journalctl -u tripplan -f` — состояние и логи
- Не запускайте второй uvicorn вручную или фоновой задачей: порт 8000 занят службой.
- Пользователь открывает приложение у себя через проброс порта 8000 в VS Code (вкладка PORTS):
  http://localhost:8000. Наружу порт не открыт, и так должно оставаться: авторизации в приложении нет.
- Если использовать `pkill -f` со строкой из команды, он убьёт и собственную оболочку.
  Останавливайте процесс по PID или через `systemctl`.

## После правок

- Backend подхватывает изменения сам. Frontend нужно пересобрать: `cd frontend && npm run build`.
- Если пользователь говорит «не работает», а тесты проходят, сначала проверьте в `journalctl -u tripplan`,
  какие запросы на самом деле шлёт браузер: возможно, у него старый `app.js`. Сервер отдаёт фронтенд
  с `Cache-Control: no-cache` (`FrontFiles` в `main.py`), но вкладку, открытую до пересборки, нужно обновить.
- Тесты: `cd backend && .venv/bin/python -m unittest discover -s tests`
- Проверка типов: `cd frontend && npx tsc --noEmit`. Ошибка про `./styles.css` в `main.tsx` была и раньше, её можно не учитывать.

## Договорённости

- Длительность в тексте для пользователя пишем как «1 ч 25 мин», «1 ч», «40 мин»:
  `fmt_dur` в `backend/app/planner.py`, `dur` в `frontend/src/FormPage.tsx`.
- Минимальная длительность пункта равна шагу кнопок −/+ из настроек поездки (`step_min`: 5, 10 или 15),
  а не фиксированные 10 минут. Это касается и формы «Добавить пункт», и `set_duration`, и `add_item`.
- Пункт, который заканчивается ровно к следующему пункту с фиксированным временем
  («Выход из дома» → посадка → поезд), при изменении длительности сдвигает своё начало,
  а время прибытия не меняется. Кнопка «−» у «Выхода из дома» означает «выйти позже»;
  новое время дороги записывается в `input.to_station_min` и в описание пункта.
- Жильё: в каталоге и отели, и квартиры имеют `category: "hotel"`, вид задаёт поле `stay` (`hotel` / `apartment`).
  Время заселения и выезда берётся из `check_in` / `check_out` варианта, иначе — обычное из `STAY_TIMES`
  (тогда в тексте пишем «обычное время, уточните в брони»). Пункты, связанные с жильём, помечены `stay_role`
  (`checkin`, `checkin_late`, `wake`, `breakfast`, `checkout`, `back`); подписи «в отель / в квартиру» формирует
  только `stay_text`. При раннем приезде утром «Оставить вещи», заселение — сразу после обеда (`checkin_step`).
- Жильё меняется только в вводных поездки (раздел «Где жить»: `stay_id` из каталога или `stay_url`), и программа
  строится заново: оно задаёт заезд, выезд и дорогу каждый день. В маршруте у жилья нет «Заменить» —
  `replace_place` отказывает, кнопка «⇄ Изменить жильё» ведёт в форму (`/?edit=…&focus=stay`).
- Квартира с Суточно.ру по ссылке «Поделиться»: `stay_url` в `POST /api/trips` → `sutochno.load`
  (разметка schema.org, если её нет — `OBJECT_MAP_DATA` и og-теги; заезд и выезд — из «Правил дома»);
  в форме её показывает `POST /api/stays/preview`. Программа строится сразу от неё: `plan_trip(raw, custom_places)`.
  Так же в поездке хранятся экскурсии Трипстера (`tripster-<id>`) и кафе по ссылке с Яндекс Карт (`ymaps-<oid>`,
  `yandexmaps.load` разбирает `<script class="state-view">` страницы организации) — их ставит `replace_with_custom`.
  Такое место хранится в самой поездке, в `trip["custom_places"]`, а не в каталоге, поэтому места ищем через
  `trip_ctx(trip)` и `ctx.find` / `ctx.place`, а не через `catalog.load(...)["by_id"]`.
