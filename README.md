# Своим ходом — прототип

Планировщик самостоятельных поездок по России. По вводным (откуда, куда, даты, время отправления, дни, транспорт, состав группы, бюджет, темп, пожелания) строит программу по часам: дорога, заселение, обеды и ужины, музеи, прогулки, театр. Пункты можно менять и удлинять, к ним можно прикладывать билеты и брони, а бюджет показывает, что оплачено, что платить на месте и что пока оценка.

Это этап 1 из плана в документе «Своим ходом — архитектура приложения»: четыре города (Санкт-Петербург, Казань, Нижний Новгород, Калининград), свой черновой каталог мест, без платных API.

## Быстрый старт (macOS)

Нужны Python 3.11+ и Node.js 20+ (`brew install python node`).

```bash
bash scripts/setup.sh   # окружение, зависимости, сборка, тесты
bash scripts/run.sh     # сервер на http://localhost:8000
```

В VS Code: File → Open Workspace from File… → `tripplan.code-workspace`. VS Code предложит установить рекомендуемые расширения — нажмите «Install». Затем Terminal → Run Task → «Установка: всё», после неё F5 — запустится сервер с отладкой.

## Аккаунты

Без входа приложение показывает страницу «Вход / Регистрация», а весь `/api/` (кроме `/api/auth/*` и `/api/health`)
отвечает 401: поездки личные, а подсказки адресов, расписания и распознавание билетов тратят платные ключи
(`RequireLogin` в `main.py`). Почта и пароль (`app/auth.py`): пароль — хеш scrypt с солью, сессия — случайный токен
в cookie `sh_session` (HttpOnly, SameSite=Lax, 30 дней), в базе — только sha256 от него. После 5 неудачных попыток
входа за 15 минут — пауза. Смена пароля закрывает остальные сессии.

У поездки есть владелец (`trips.user_id`): чужую поездку и её файлы сервер не отдаёт (404, как несуществующую).
Билеты, загруженные в форме до создания поездки, лежат в папке пользователя (`pending-<user>-<token>`).
Поездки, построенные до появления аккаунтов, при первой регистрации достаются первому пользователю.
«Мои поездки» (`/trips`) — список, удаление и карточка «Пользователь» (имя, почта, смена пароля). Дальше по плану — вход через Яндекс ID и VK ID.

### Забыли пароль

На странице входа кнопка «Забыли пароль?» просит почту, и `POST /api/auth/forgot` отправляет письмо со ссылкой
`/reset?token=…` (`app/mailer.py`). Токен одноразовый, живёт 2 часа, в базе (`resets`) — только sha256 от него;
новый пароль закрывает все сессии пользователя и остальные выданные ссылки. Писем — не больше трёх в час на аккаунт.
Есть такая почта или нет, ответ один и тот же: иначе по нему можно узнать, кто зарегистрирован.

Почта настраивается в `backend/.env` по образцу `backend/.env.example`: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`,
`SMTP_PASSWORD`, `SMTP_FROM` и `APP_URL` (из него собирается ссылка в письме). Ящик на reg.ru: хост — из панели
у ящика (обычно `mail.hosting.reg.ru`), порт 465, пользователь — полный адрес, пароль — пароль ящика.
Для Яндекс 360 (`smtp.yandex.ru:465`) нужен пароль приложения из Яндекс ID: обычный пароль аккаунта SMTP не принимает.
Без настроек письмо не уходит, а пишется в журнал (`journalctl -u tripplan`), так что ход восстановления можно
проверить и без почты. Проверить сами настройки: `cd backend && .venv/bin/python -m app.mailer адрес@почта.ru`
(после правки `.env` — `systemctl restart tripplan`).

## Подсказки адресов

Поле «Адрес, откуда выходите» подсказывает адреса при вводе и по выбранному адресу оценивает время дороги до вокзала или аэропорта.

- **Без настройки** подсказки идут через Photon — бесплатный сервис на данных OpenStreetMap. Подходит для разработки, но при большой нагрузке может ограничивать запросы.
- **Для лучшего качества по России** подключите DaData: зарегистрируйтесь на dadata.ru, скопируйте API-ключ, создайте файл `backend/.env` по образцу `backend/.env.example` и впишите `DADATA_API_KEY=ваш_ключ`. Перезапустите сервер.

### API

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | /api/auth/register, /api/auth/login | `{"email", "password", "name"}` → cookie сессии |
| POST | /api/auth/logout | выйти |
| GET | /api/auth/me | кто вошёл (401 — никто) |
| POST | /api/auth/password | `{"old", "new"}` — сменить пароль |
| POST | /api/auth/forgot | `{"email"}` — письмо со ссылкой на новый пароль |
| GET/POST | /api/auth/reset | годна ли ссылка `?token=…` / `{"token", "password"}` — новый пароль и вход |
| GET | /api/trips | мои поездки |
| DELETE | /api/trips/{id} | удалить поездку с файлами |
| GET | /api/meta | справочники формы |
| GET | /api/stays | варианты жилья для формы: `city`, `start_date`, `end_date`, `adults`, `kids`, `budget`, `stay` |
| POST | /api/stays/preview | объявление Суточно.ру по ссылке для формы: `{"url": …, "city": …}` |
| POST | /api/bookings | распознать билеты и брони: form-data `file` (PDF, можно несколько), `text`, `origin`, `city` |
| POST | /api/trips/{id}/items/{item}/place | своё кафе по ссылке с Яндекс Карт вместо еды: `{"url": …}` (`app/yandexmaps.py`) |
| POST | /api/trips | построить поездку; `return_transport` — на чём обратно, `stay_id` — жильё из каталога, `stay_url` — своя бронь на Суточно.ру |
| GET | /api/trips/{id} | открыть поездку |
| PATCH | /api/trips/{id}/items/{item} | `{"duration": 90}` или `{"replace_with": "place_id"}` (кроме жилья — оно меняется в вводных) |
| POST | /api/trips/{id}/items/{item}/doc | приложить документ: form-data `file` (можно несколько), `sum`, `paid`, `title`, `date`, `start`, `end` |
| DELETE | /api/trips/{id}/items/{item}/doc | убрать документ |
| DELETE | /api/trips/{id}/items/{item}/doc/files/{name} | убрать один файл документа |
| DELETE | /api/trips/{id}/items/{item} | убрать пункт из программы |
| GET | /api/trips/{id}/days/{day}/suggest | что можно добавить в день |
| POST | /api/trips/{id}/days/{day}/items | добавить пункт: `{"after": id, "place_id": …}` или `{"title": …, "duration": 60}` |

Примеры запросов — в `api.http` (расширение REST Client).

## Как подбираются места

- **Важность** (`priority` 1–5) проставлена в каталоге вручную. К ней добавляются бонусы: за совпадение тегов места (`tags`)
  с интересами из формы или из текста пожеланий (история, искусство, архитектура, природа, виды, местная кухня),
  за пометку «интересно детям» и за упоминание места в пожеланиях (шаблон `keywords`, например «хотим в Свияжск»).
- **Выезд за город** (`category: "daytrip"`, например Свияжск, Раифа) занимает полдня. Его ставят на полный день
  в середине поездки, с утра. Время и способ дороги берутся из поля `far`; если `far.lunch`, обед входит в выезд.
- **Новый город** — это файл `data/<город>_places.json` (`city`, `aliases`, `center`, `arrival_points`, `places`)
  и оценка дороги из Москвы в `ROUTES` в `planner.py`. После добавления перезапустите службу.
- **Рейтинг и часы кафе и ресторанов** в каталоге берутся с Яндекс Карт скриптом `tools/yandex_facts.py` в два шага
  (поиск по названию находит и соседние заведения, поэтому id выбирают глазами):

  ```
  cd backend
  .venv/bin/python -I tools/yandex_facts.py data/spb_places.json           # кандидаты рядом с координатами
  .venv/bin/python -I tools/yandex_facts.py data/spb_places.json --write   # по ymaps_id -> rating, reviews, hours
  ```

  Закрытые на Картах заведения (`permanent-closed`, `temporary-closed`) скрипт не обновляет, а печатает
  «! … закрыто, замените его в каталоге». Если Карты отвечают ошибкой на частые запросы, он ждёт и повторяет запрос.
  Кандидатов ищет в радиусе 400 м от координат места: если нужного заведения нет, сначала проверьте координаты.

  В описании пункта с едой хвост собирает `food_item` из полей места: `rating`/`reviews` —
  «★ 4,5 на Яндекс Картах (211)», `hours` — «Работает 09:00–21:00, пт и сб до 01:00, выходной пн» (`hours_text`).
  Так же выводятся кафе по ссылке с Яндекс Карт — у них те же поля из `yandexmaps.parse`.

## Что упрощено в прототипе

- **Каталог мест черновой.** Координаты и цены приблизительные; у кафе и ресторанов Санкт-Петербурга и Казани рейтинг и часы
  сверены с Яндекс Картами (`tools/yandex_facts.py`), у остальных мест часы приблизительные, рейтинга нет.
  Рестораны и отели помечены «(подбор)»: в MVP их заменят результаты Яндекса и партнёров.
- **Переходы считаются по прямой** с коэффициентом 1,3: пешком до 2 км, дальше метро или такси. В MVP — Матрица расстояний Яндекса.
- **Дорога из Москвы** — средние время и цена. В MVP — Яндекс.Расписания и цены партнёров.
- **Документы:** сумма, дата и время вводятся вручную, распознавания пока нет. Введённые данные сверяются с программой: дата, выходные дни, часы работы, время по билету.
- **Фото мест** — миниатюры из Википедии (нужен интернет), рестораны и отели — ссылками «рядом на Яндекс Картах», пока нет данных Яндекса.
- **Сервер на Starlette.** FastAPI построен на ней, поэтому перенос — замена `Route` на декораторы.
- **SQLite вместо PostgreSQL.**

## Разбор пожеланий (YandexGPT или Claude)

Свободный текст пожеланий при создании поездки разбирает языковая модель (`app/wishes_ai.py`): интересы,
флаги (театр, подешевле…), чего избегать («без музеев»), какие места обязательно и куда не надо, темп. Темп из текста
подставляется, только если в форме оставлен темп по умолчанию. На странице поездки видно, как поняли пожелания.

- **YandexGPT** (по умолчанию, доступна в России): в `backend/.env` впишите `YANDEX_GPT_API_KEY` (API-ключ сервисного
  аккаунта с ролью `ai.languageModels.user`) и `YANDEX_FOLDER_ID` (каталог в Yandex Cloud, `b1g…`).
  Модель — `YANDEX_GPT_MODEL`, по умолчанию `yandexgpt/latest` (Pro); дешевле — `yandexgpt-lite/latest`.
- **Claude**: `ANTHROPIC_API_KEY`; если заданы оба ключа — `LLM_PROVIDER=anthropic`.

После правки `.env` — `systemctl restart tripplan`. Один вызов на поездку; результат хранится в `input.wishes_ai`
и переиспользуется, пока текст не поменяли. Ответ модели проверяется: в настройки попадают только известные значения
и места этого города. Без ключей, при отказе модели или ошибке сети — прежний разбор по ключевым словам.

## Экскурсии Трипстера

С `TRIPSTER_PARTNER` и `TRIPSTER_SECRET` в `backend/.env` (партнёрский API 2.0, `app/tripster.py`) у музеев,
достопримечательностей, прогулок и выездов за город появляется свёрнутый блок «Экскурсии с гидом сюда»: до трёх
экскурсий с ценой, длительностью и рейтингом. Подбор — по словам из названия места (координат у экскурсий нет).
Каталог города загружается целиком раз в сутки в фоне (при старте сервера и при устаревании) и хранится
в `backend/var/tripster/`; Петербург — около 25 страниц и 5 минут. Ссылки — с метками партнёра (`exp_partner`, `utm_*`),
пометка «Реклама» и `erid` — из `ad_info` партнёра в API.
Экскурсию можно поставить в программу вместо места через «⇄ Заменить» (`replace_with: "tripster-<id>"`):
она сохраняется в поездке (`custom_places`, `category: "excursion"`), цена за человека — на всю группу,
цена за экскурсию (`price_group`) — один раз, ссылка «Забронировать — Трипстер» — партнёрская с маркировкой.

## Билеты и брони в форме

Раздел «Уже есть билеты или брони?»: PDF из писем (или текст письма) -> `POST /api/bookings` -> `app/bookings.py`:
текст из PDF достаёт pypdf, поля раскладывает YandexGPT (или Claude) по схеме — вид (поезд, самолёт, автобус, театр,
музей, экскурсия, жильё), дата, время начала и окончания, номер, города, площадка, цена, число мест. Роль брони:
`out`/`back` заполняют «Туда»/«Обратно» (и даты поездки), `stay` — «Где жить» (своя бронь), `event` — жёстко
встаёт в программу дня: вечерние (с 17:00) как театр с ужином до него, дневные — местом с фиксированным началом,
остальные места раскладываются вокруг (`plan_trip(raw, custom_places, events)`). Файлы до создания поездки лежат
в `var/uploads/pending-<token>/`, при создании переносятся к своим пунктам документом «оплачено».
Фото и скриншоты (JPG, PNG) и сканы PDF без текстового слоя читает Yandex Vision OCR: `YANDEX_VISION_API_KEY`
(сервисный аккаунт с ролью `ai.vision.user`, ключ с областью `yc.ai.vision.execute`), каталог — `YANDEX_FOLDER_ID`
или `YANDEX_VISION_FOLDER_ID`. У скана из нескольких страниц синхронный OCR читает только первую.

## Расписание поездов, самолётов и автобусов

Ключ API Яндекс.Расписаний бесплатный: https://yandex.ru/dev/rasp/raspapi → «Получить ключ».
Впишите его в `backend/.env` строкой `YANDEX_RASP_API_KEY=...` и перезапустите сервер (Shift+F5, F5).
С ключом в форме появляется кнопка «Выбрать из расписания», а при вводе номера поезда или рейса
время отправления и прибытия подставляется само. Без ключа время вводится вручную.
